# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Docker base image (`dwchiang/nginx-php-fpm`) that merges nginx and php-fpm into a single container, managed by supervisord, for running Laravel and other PHP apps on cloud-native platforms (AWS Fargate, ECS/EKS, amd64/arm64). Images are published to Docker Hub and AWS ECR Public (`public.ecr.aws/n0b9n5m7/nginx-php-fpm`).

Two-part design:
- Part 1 (this repo): the base image Dockerfiles under `Dockerfiles/{OS}/`.
- Part 2 (user side): the consumer's own Dockerfile that `FROM`s this image and installs the PHP extensions their app needs. Reference Part 2 examples live in `Testings/` and are never published.

## Generated Dockerfiles — do not hand-edit

Every `Dockerfiles/{OS}/Dockerfile-*` file is generated by an external upstream toolkit (see the header comment in each file). They are mechanical merges of the official `php:*-fpm-*` and `nginx` Dockerfiles plus this project's supervisord/nginx config. Editing one file by hand is almost always wrong: the change will be lost on the next toolkit regeneration and will not propagate to the other ~hundreds of OS/PHP/nginx combinations. `docs/Maintenance.md` describes the old manual workflow and is explicitly deprecated by the toolkit. Real changes to image behavior belong in the toolkit or in the per-OS `conf/` and `scripts/` directories.

## Build / release

Builds are driven by `Dockerfiles/Makefile` with version env vars; `Dockerfiles/build.sh` is the local entrypoint that sets them and calls `make`. Run from inside `Dockerfiles/`.

```sh
cd Dockerfiles
export VERSION_OS=trixie
export VERSION_NGINX=1.31.0
export VERSION_PHP=8.5.6
export IS_LATEST=true

make version   # print resolved version matrix, verify before building
make build     # local single-arch build, tags :{VERSION} (+ :latest if IS_LATEST=true)
make release   # multi-arch buildx (amd64,arm64) + push to Docker Hub AND AWS ECR Public
make releaseDockerHub   # same but Docker Hub only
```

`VERSION` resolves to `{VERSION_PHP}-fpm-{VERSION_OS}-nginx-{VERSION_NGINX}`, which is both the image tag and the Dockerfile filename selected (`{VERSION_OS}/Dockerfile-{VERSION}`). `release` requires AWS CLI v2 auth (ECR Public) and a Docker Hub token at `~/.docker/dhtoken.txt`; it does a full `docker system prune` first (`cleandocker`). `make build.sh` itself just sets the four exports and runs `make $BUILD_CMD`.

## Test (Laravel smoke test)

```sh
cd Testings
export VERSION_LARAVEL=9.1.10        # must match a docker-compose-{VERSION_LARAVEL}-laravel.yml
make -f ../Dockerfiles/Makefile test # or run docker-compose directly
# brings up database+cache+app; app at http://localhost:8082/ , MySQL :33062 , Redis :63792
make ... seedlaravel   # php artisan migrate + db:seed inside the app container
make ... down          # tear down
```

There is no unit-test suite; "testing" means building a Part 2 Laravel/phpinfo image and running it via the matching `Testings/docker-compose-*.yml`.

## Repo layout

- `Dockerfiles/{OS}/` — generated base Dockerfiles. OS codes: `trixie`, `bookworm`, `bullseye`, `buster`, `alpine3.13`–`alpine3.23`.
- `Dockerfiles/{OS}/conf/` — `nginx.conf`, `nginx-default.conf`, `supervisord.conf` baked into images for that OS.
- `Dockerfiles/{OS}/scripts/` — nginx `docker-entrypoint.sh` and `/docker-entrypoint.d/*` helpers (e.g. `30-tune-worker-processes.sh`).
- `Testings/` — Part 2 reference Dockerfiles + docker-compose files (consumer-side examples).
- `docs/Tags.md` — canonical published-tag list; `docs/Benchmark.md`; `docs/Maintenance.md` (deprecated).
- `CHANGELOG.md` — date-keyed log of added PHP/nginx/OS versions.
- `scripts/gen-star-history.py` — regenerates `docs/star-history.svg` and `docs/star-history.json` from the GitHub stargazers API. Standard library only; do not add a plotting dependency. The footer carries both the last-star date and the generation date; the latter is an intentional heartbeat, so every scheduled run commits even when the star count is unchanged. That is the only signal for a workflow that stops running altogether, which raises no alert of its own.
- `.github/workflows/star-history.yml` — runs that script on the 1st and 15th of each month. It must use the `STAR_HISTORY_TOKEN` secret: the default Actions `GITHUB_TOKEN` is rejected by the stargazers endpoint with 403. If the chart silently stops updating, the token has most likely expired.
- `backup/` and `*.log` are gitignored (build/cron logs accumulate in `Dockerfiles/`).

## Runtime architecture (inside the image)

supervisord runs `php-fpm -F` (priority 10) and `nginx -g 'daemon off'` (priority 20), both with `stopsignal=QUIT`, logs to stdout/stderr. nginx (`conf/nginx-default.conf`) serves static files from `/usr/share/nginx/html/`, the PHP app from `/var/www/html` with the doc root at `/var/www/html/public`, proxying `.php` to php-fpm on `127.0.0.1:9000`. It includes a `fastcgi_cache` ("dwchiang" zone, skipped on POST / auth / `laravel_session` cookie), AWS ELB real-IP handling (`X-Forwarded-For`), and Laravel HTTPS detection via `X-Forwarded-Proto`. PHP extensions are intentionally minimized — consumers add what they need in Part 2. Extra config can be dropped at `/etc/nginx/conf.d/*.conf`, `/etc/supervisor/conf.d/*.conf`, and executable `/docker-entrypoint.d/{number}-{name}.sh`.

## When adding a new version

Adding a PHP / nginx / OS version means running the upstream toolkit to regenerate Dockerfiles (not copying files by hand), then updating `docs/Tags.md` (current naming rule: `{PHP}-fpm-{OS}-nginx-{NGINX}`), `CHANGELOG.md`, and the Quick Reference lists in `README.md`. Old combination Dockerfiles are kept, never deleted, so existing users can still reference them.
